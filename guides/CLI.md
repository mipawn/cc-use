# 命令行工具使用指南

`cc-use` 只是终端客户端的启动入口，不承担实例管理、切换或统计。Codex Desktop 与
Claude Desktop 继续在桌面应用里打开和管理。

## 安装

应用 → 设置 →「命令行工具」→ 安装。它会把应用内二进制链接到
`/usr/local/bin/cc-use`。

## 使用

```bash
cd 你的项目目录
cc-use claude
cc-use grok
```

两个命令都会：

1. 显示该客户端可用的供应商与密钥列表；
2. 预选 GUI 中当前项目为该客户端配置的默认线路；
3. 用上下方向键高亮选择，回车使用当前项；
4. 按 `q` 取消；确认后在当前终端启动客户端，不弹出新终端窗口。

选择只影响本次启动，不修改 GUI 默认配置。当前目录未配置项目时，仍会列出全部兼容
线路，并预选第一项。daemon 未运行时会直接提示先打开 CC Use，不会启动一个无法请求的
客户端。

CLI 的公开命令只有 `claude` 和 `grok`。运行后的线路管理、用量查看与默认配置都在 GUI
中完成。

设置页同时提供更新、重新安装与卸载。卸载只移除 `/usr/local/bin/cc-use`，不会删除应用、
配置或用量数据。

## 项目前置命令

CLI 会按当前目录匹配项目；当前目录是项目子目录时，优先匹配路径最深的项目。
匹配成功后，除了预选该客户端的默认线路，还会读取在 GUI 项目编辑页配置的「启动前命令」。
切换本次启动使用的密钥不会丢弃项目前置命令。

确认线路后，先在调用 CLI 的当前目录执行前置命令，再启动客户端。命令中 `export` 的
环境变量会传给客户端；命令返回非零退出码时，中止启动并返回该退出码。
未匹配项目或未配置命令时直接启动客户端；不会执行其他客户端的项目前置命令。

v3.9.2 补齐了客户端绑定未保存命令时，从同客户端项目配置读取命令的处理。
更新应用内 CLI 即可生效，无需重新配置；若终端仍使用旧版，可在设置页重新安装命令行工具。

## Claude Code 状态栏

状态栏是独立的可选能力：进入 Claude Code 页 → 右上角「客户端设置」→「状态栏」，由用户主动启用。
它以彩色双行状态栏显示模型、Git 分支、上下文占用、缓存命中率，以及当前 CC Use 实例、供应商
和 Key；不依赖全局安装 CLI。普通 Claude Code 会保留模型、Git、上下文与缓存信息，并把
线路标记为 `unmanaged`。

已有第三方 `statusLine` 时，界面会让用户选择保留现有配置或备份并覆盖；点击恢复会还原
被替换的第三方配置。Claude Code 会在下一次交互时自动刷新，无需重启。

从 v3.13.0 起，第二行显示 `Cache 85.0%`，读取 Claude Code 当前状态栏数据中最近一次 API
响应的用量，计算「缓存读取 ÷（普通输入 + 缓存读取 + 缓存创建）× 100%」，保留一位小数。
输出 Token 不参与计算；每次状态栏刷新重新读取，不累积会话历史，也不读取其他窗口的用量。
首次响应前、`/compact` 后、字段缺失或无有效输入时显示 `Cache —`；有输入但缓存读取为零时显示 `Cache 0.0%`。
已启用用户升级后无需重新启用；应用位置变更时用「更新路径」修正配置。

## 退出码

| 码  | 含义                                 |
| --- | ------------------------------------ |
| 0   | 成功                                 |
| 1   | 服务未运行、没有兼容线路或启动失败   |
| 2   | 当前不是可交互终端，无法完成列表选择 |
