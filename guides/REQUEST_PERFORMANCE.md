# 请求响应速度

v3.14.0 在「用量与日志 → 用量统计」中增加输出速度和首 Token 延迟，原「延迟」明确为「总耗时」。

## 查看位置

- 顶部汇总显示平均首 Token 延迟和平均输出速度。
- 最近请求和请求详情分别显示输出速度、首 Token 延迟与总耗时。
- 供应商 / Key 用量详情增加平均输出速度，以及「响应速度」趋势视图；沿用现有时间范围筛选。

## 指标含义

| 指标          | 含义                                                                                   |
| ------------- | -------------------------------------------------------------------------------------- |
| 首 Token 延迟 | 请求进入代理，到首次收到文字、思考或工具调用内容的时间；心跳、空事件和连接元数据不计入 |
| 总耗时        | 请求进入代理，到响应流结束的时间；包含请求等待和输出过程                               |
| 输出速度      | 输出 Token × 1000 ÷（总耗时 ms − 首 Token 延迟 ms），单位 t/s                          |
| 平均输出速度  | 所选范围内，有有效计时的成功流式请求逐条计算速度后取算术平均                           |

例如，先等待 2 秒，再用 10 秒输出 1000 Token：首 Token 延迟约 2 秒，总耗时约 12 秒，输出速度约 100 t/s。

速度不计输入和缓存 Token，也排除了首 Token 前的等待；它是代理观测值，包含输出期间的网络和收尾开销。上游报告的输出 Token 可能包含思考 Token。比较线路时，结合相同模型、相近任务、首 Token 延迟和成功率阅读这些数值。

## 升级与缺失数据

更新应用后，在「设置」中重启本地服务，新请求开始采集。无需数据库结构迁移。

历史、非流式、没有有效输出事件或无法准确计时的记录显示 `—`。当前仍采用结束后解压的压缩 SSE 不提供测速；失败、取消、零输出和没有正生成时长的样本不计入平均速度。无有效测速样本时显示 `—`，不显示为 0 t/s。

支持 Anthropic Messages、Chat Completions 和 Responses 的 SSE 输出。测速结果在请求结束后写入，刷新用量统计即可查看。
