# 3.14.2 基线重启：网关出口与体验修复

## Goal

以已发布的 **v3.14.2** 为唯一产品基线，放弃 v4 全量重写。在保留 3.x 现有能力的前提下，新增**常驻网关出口**能力（可建多个，每个只绑一个密钥），并修复 5 项已确认的体验/正确性问题，让核心流程重新可用。

用户价值：供应商与密钥、CLI 启动、Desktop 接管、用量统计继续沿用 3.x 已验证的实现；新增的网关只做“绑定一个密钥并原样转发”，不引入新的协议层或运行实例模型。

## Confirmed Facts

- 发布基线：tag `v3.14.2`。`main` 相对该 tag 只多出 Trellis/文档等工具文件，产品代码一致。
- 开发分支：`feat/v3.14.2-gateway-relaunch`（从 `main` 创建）。旧 `codex/v4-product-focus` 分支保留、不删除。
- 3.x 的 daemon 已经是常驻 LaunchAgent，是唯一持有真实密钥的数据面进程；客户端只拿 session token。
- 3.x 的请求路径是透明转发：按密钥/供应商解析上游后原样转发请求，不做协议互转。
- 网关必须遵守既有安全边界：真实上游密钥不得出现在客户端配置、日志或响应中。

## Requirements

### R1 网关出口

- 新增独立“网关”页面，用于创建、查看、编辑、删除、启用/停用网关。
- 允许创建**多个网关**，**每个网关只能关联一个密钥**（供应商 + API Key）；不关联模型、规则、项目或运行实例。
- 网关对外提供常驻出口：本机地址 + 网关本地 Key。客户端用该本地 Key 认证，daemon 解析到绑定的那一个密钥并转发。
- 兼容 OpenAI 协议的模型发现：客户端使用网关根地址；网关复用供应商已配置的「查询模型」逻辑处理 `/models`，并在转发时按供应商 base URL 补 `/v1`。鉴权使用密钥连接配置的 authScheme；User-Agent 优先用密钥转发 UA，未设置时回退到供应商查询 UA。
- **只做透明转发**：客户端请求什么路径、方法、Body、model 就转发什么；不做协议转换，不承诺同时兼容两种协议，不新增模型映射/改写逻辑（绑定 Key 上的模型映射对网关不生效）。
- 常驻由现有 daemon 承担：不为网关创建进程、不做单网关启停、不新增 session/实例心跳。
- 网关停用或绑定密钥不可用时，请求明确失败并记录原因；不得静默回退到其他密钥。

### R2 供应商配额 UI

- 修复“5h 额度”区域的上下间距，避免与相邻内容粘连。
- 修复查询/刷新按钮突兀的问题：位置、层级与视觉权重和所在区域协调，不单独悬空。

### R3 Claude Code Auto mode

> 2026-10-26 更新：本条的实施方式由子任务 `10-26-auto-mode-local-classifier-env` 替代。默认仍不注入；按 Key 开启兼容后改为注入 `CLAUDE_CODE_AUTO_MODE_SERVER=0` 与 `CLAUDE_CODE_AUTO_MODE_MODEL`，并移除代理侧改写。

- **默认完全不动 Claude Code 的请求**：不启用适配时不改 auto-mode 相关的 `model`、`thinking`、`output_config.effort`、`max_tokens` 或采样参数；普通请求与最新版 auto mode 的 `safeguards` / `safeguard_results` / `anthropic-beta` 一律原样透传。Key 已配置的常规模型映射仍按既有语义执行。
- 保留“Auto mode 兼容适配”能力，用于**不支持 Claude Code 原生 auto mode 的供应商**：
  - **默认不注入任何 auto-mode 启动环境变量**；显式开启兼容的子任务可注入本地分类器 env（见子任务 PRD）。
  - 代理不再改写分类器请求的 `model` / `thinking` / `effort`；分类器模型由启动环境变量指定。
- 新 Key 默认不开启适配；UI 说明这是“兼容适配”，不是 auto mode 的开关。
- 不新增协议转换，不改变普通请求的转发语义。

### R4 仅菜单栏常驻

- macOS 上只保留顶部菜单栏状态项，**不再显示 Dock 图标**。
- 关闭窗口后仍可从菜单栏打开；不因隐藏 Dock 图标导致窗口无法唤回或退出路径丢失。

### R5 供应商模型添加

- 供应商模型一律由用户**主动选择后添加**；获取模型列表不得自动写入/启用模型。
- 区分“获取到的候选模型”和“已添加模型”，保存动作必须由用户显式触发。
- 刷新获取结果不得覆盖用户已添加的自定义模型。

### R6 控制台异常真实性

- 请求失败、上游错误、传输失败、客户端中断等异常，不得在控制台显示为成功。
- 每条异常必须记录可定位的原因（至少包含 HTTP 状态或错误消息），并在控制台可见。
- 成功、失败、取消三类状态口径一致，不把取消算作成功或上游失败。

## Acceptance Criteria

- [ ] R1：新建网关并绑定一个密钥后，用该网关地址 + 本地 Key 调用上游接口成功；换绑另一个密钥后同一网关请求走新密钥；停用后请求明确失败。
- [ ] R1：网关请求只影响绑定的那一个密钥，不会落到其他密钥；真实上游密钥不出现在客户端配置或日志。
- [ ] R1：daemon 重启后网关仍可用，无需重新创建或手动启动网关。
- [ ] R2：1440/1280/1024 宽度下，“5h 额度”区块与相邻元素有稳定间距；查询按钮与所在区域对齐，无悬空感。
- [ ] R3：适配关闭时，最新版 Claude Code 经 cc-use 的请求/响应（含 `safeguards` / `safeguard_results` / `anthropic-beta`）原样透传，auto-mode 适配不额外修改 model/thinking/effort。
- [ ] R3：适配开启时，不注入任何启动环境变量；客户端分类器/辅助请求的 model 被映射到可用模型；默认不改 thinking/effort；`low` 只设 effort；`disabled` 生效；不产生 `thinking.type.enabled` 类 400；新 Key 默认关闭适配。
- [ ] R4：启动应用后 Dock 无图标，顶部菜单栏有状态项；关闭窗口后可从菜单栏重新打开；应用可正常退出。
- [ ] R5：获取模型后不自动添加；用户勾选并保存后模型才出现在已添加列表；再次获取不覆盖自定义模型。
- [ ] R6：构造上游 4xx/5xx、连接失败、200 截断流、客户端中断四类场景，控制台分别显示失败/取消及原因，不显示成功；`request_logs.outcome` 与控制台口径一致。

## Out of Scope

- 不恢复 v4 的网关/规则/模型三层配置模型。
- 不做协议互转、双协议兼容承诺、任意工具调用任意协议模型。
- 不新增网关级统计、多用户、组织、计费体系。
- 不删除 3.x 已有的项目/实例/CLI 启动/Desktop 接管能力。
- 不重构与上述 6 项无关的模块。
