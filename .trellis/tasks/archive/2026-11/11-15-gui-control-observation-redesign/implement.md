# 实施与验证计划

## 启动门槛与组织

当前状态：用户已明确批准完整方案并授权产品实施；任务已启动，工作分支为 `gui-control-observation-redesign`。不启动真实客户端服务。改动前 `pnpm typecheck && pnpm lint && pnpm test` 与 `cargo test --workspace` 均通过（exit 0）。

采用一个集成任务、依赖有序的内部工作包；不是多轮产品发布。主代理负责共享类型、API与路由集成；若委派独立页实现，先确定文件归属，共享契约冻结后再并行，不让多个代理同时覆盖共享文件。提交代码前必须由集成者审查最终diff并执行测试。

## P0 基线与安全验证入口

- 批准后加载 `trellis-before-dev`，读取本包前后端规范及CLI兼容契约；复核工作区有无用户新改动。
- 记录基线测试结果，启动Trellis实施阶段。只在用户现有工作区开展，不自行提交/发布。
- 定义跨层DTO和API调用矩阵；增加strict fixture API与事件源，支持内存变更和失败注入；未知方法throw，不回退真实Tauri API。
- 浏览器fixture网络只允许静态预览源，不访问daemon、供应商、Keychain或真实配置；用独立ego TaskSpace，精确记录URL与进程归属，不替换DSH GUI或现有服务。
- 完成条件：无真实IPC时demo也可正常运行，未覆盖方法显式失败；基线与测试限制有记录。

## P1 最小跨层契约

- 定义共享RequestLogFilter：资源/实例稳定ID、outcome、population；复用本地日期range，严格校验。
- 统计聚合/趋势/总数/分页共用参数化筛选；保留billable和failed原有分母规则；已删除scope报清楚而非全量。
- 新增控制台按requestId只读精确查询：保留留存/截断元信息，在limit前匹配；不改落盘schema。
- 定义Desktop状态与操作结果、可见同步失败记录；更新Rust模型、命令、注册、Api、buildApi与fixture，覆盖托盘与自动profile同步调用。
- 配置操作用临时路径与测试库覆盖文件/session不一致，优先回滚，否则partial+真实回读；回读失败unknown。
- 完成条件：IPC契约与后端单测先通过；原调用缺省参数语义保持；不新增破坏性数据库迁移。

## P2 页面骨架与导航

- 重组Sidebar、TitleBar和HashRouter，新增统一实例/桌面接入路由，旧四客户端入口redirect。
- 首页仍是概览；删除主窗口项目入口和托盘最近项目子菜单，保留项目数据/API/共享CLI启动依赖。
- 增加统一标题/上下文标记/状态块，保留主题token、侧栏折叠、拖拽区域和页面刷新机制。
- 完成条件：所有新旧路由可达，页面没有项目启动入口，CLI仅过时提示改名而行为未变。

## P3 资源配置与选线闭环

- 复用ProviderModal、KeyEditModal核心表单，增加返回创建对象的协调层；避免复制复杂查询/模型字段逻辑。
- 重组资源页并自动定位新供应商；保存与额度刷新分离，但保留保存后自动刷新触发。
- 选择器支持client/gateway上下文；额度单位/归属/窗口/时间与不可用原因明确；维护排序只留资源页。
- 创建/取消/失败/返回选择器保留目标与草稿，异步数据刷新不重置选择；应用前再次验证资源状态。
- 网关换线不清空/放宽模型策略，连接覆盖独立；供应商仍唯一模型清单管理入口。
- 完成条件：A10–A12、A16关键组件回归通过。

## P4 运行控制与Desktop整合

- 完整活跃实例使用无参数list，历史分客户端recent列表；去重/别名/范围标识准确，Claude会话/工具可达。
- 换线统一选择器、行级pending；提交失败和实例停止并发不丢选择，不改默认绑定或别的实例。
- 统一Desktop页面交互和typed API；持久化最新配置变更说明，纯换线不能清除，幂等启动同步不刷版本。
- 保存密钥但profile同步失败、恢复官方后的重开说明、检测失败与partial均有可见状态/下一步。
- 完成条件：A5–A9通过；所有操作在fixture和临时目录内验证，不调用真实takeover/restore。

## P5 观测主链路

- 首页日期/指标→统计URL，with_usage/failed口径正确；热力图键盘导航与错误重试。
- 实例、供应商、Key及资源用量弹窗→范围账本；过滤变化重置分页，刷新/返回保持scope。
- 请求详情→控制台定位；独立定位投影避免全局500裁剪，清空generation防迟到数据复活；保留终端式单行流，不添加复杂资源筛选界面。
- 读取失败、未知scope、删除关联、无请求ID、无留存记录分别展示真实反馈。
- 完成条件：A1–A2、A13–A15通过；URL只含允许的非敏感ID与筛选。

## P6 完整验收与收尾

- 加载 `trellis-check`，检查共享类型/所有invoke映射、SQL过滤与分母、权限边界、异步竞态、双语和样式规范。
- 执行下列质量门；失败先定位是否基线，不以重试覆盖真实失败。Rust测试只操作fixture/临时目录，不运行dev:daemon或真实takeover。

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build:frontend
cargo test --workspace
```

- 先跑变更相关测试迭代，再完整运行；CLI与daemon相关suite必须在workspace测试中覆盖。若有环境依赖阻断，报告准确命令/退出码，不声称全绿。
- 使用ego-browser验证六条关键旅程：①日期/失败钻取与返回；②混合客户端换线/失败重试；③无Key创建再回原操作；④Desktop写配置/纯换线/恢复/partial；⑤Key保存成功但额度或配置同步失败；⑥范围账本→控制台留存/无记录/读取失败。
- 主题×语言×窗口做主页面快照（浅/深、中/英、1440×1000/900×700），键盘和空/加载/错误/长名称/耗尽状态专项检查。
- 验证生产构建不会启用demo，关闭不再使用的测试服务和TaskSpace；不动用户的daemon或客户端。
- 逐项记录PRD A1–A20结果、截图/测试证据及原生未验证边界。清理确认无消费者的renderer旧项目组件；保留后端/CLI兼容实现。
- 主代理审查最终diff：无私密信息、无产品数据删除、无模型范围放宽、无过时代码/注释、无意外依赖更新。按Trellis收尾流程更新相关架构规范与任务记录；不擅自git commit。

## 依赖、回退与证据

P0→P1→P2，随后P3资源契约就绪后P4/P5页面可按互斥文件分工，最终P6统一集成。共享类型/bridge/locale/路由只由集成者编辑或明确移交；任何脚本全量格式化必须先确认没有并发写入。

不需要数据迁移即可退出项目UI；回退代码能恢复旧导航，新settings与可选API兼容旧数据。统计/控制台新增只读能力不改采集。实施新增的查询/状态契约写入对应spec，旧设计决定不通过重复历史追加来稀释。
