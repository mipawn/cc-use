### R4 / R9.2 唯一模型获取入口与映射联动

- **高优先级缺陷**：供应商有查询结果但密钥选择/映射不能顺畅使用；只共享底层 hook、保留重复获取入口不满足需求。查询/解析底层已经共用，不另写解析器；原差异及未复现限制见 [research.md:38–58](<.trellis/tasks/10-28-gateway-console-provider-ux/research.md#L38-L58>)。
- **入口已由用户确认**：改造供应商/密钥列表外层的“查看模型”，打开该供应商的独立“模型管理”窗口，不再跳进 Key 编辑/映射，不新增模型页面。窗口内显式选择密钥、可编辑/恢复默认的 Base URL、UA；显示实际查询连接，不暗选客户端配置。当前外层入口重新打开映射的证据：[Keys.tsx:461–473](<src/renderer/pages/Keys.tsx#L461-L473>)。
- 选中的 Key 只决定查询凭据；Base URL/UA 是独立查询草稿，修改或获取不反向修改 Key、供应商、网关或内置客户端连接。保留特殊认证能力于查询高级设置，不通过某个隐含 clientKind 改变实际查询。无 Key 可手工管理模型，但不能发凭据查询。
- 模型管理中区分本次获取的候选、手动条目和保存到该供应商的模型清单。获取只更新当前身份的候选，不自动选择、不保存配置；搜索名称/ID、勾选、已选列表、当前结果批选、单项移除及手动 ID/名称校验去重可用。
- 显式保存模型清单后持久化并供 Key 映射、客户端模型选择与绑定该供应商的网关读取，重开/重启不依赖五分钟缓存或再次获取。清单是可选模型来源，不承诺换一把 Key 或地址也一定有调用权限；上游仍验证实际能力。
- 模型映射、Key 模型选择和网关页面不再发起模型获取，也不自动用另一条网络查询补齐空候选。它们读取已保存供应商清单，并保留当前草稿、手动模型和已配置但清单未列出的 ID；缺少清单时提示到外层管理，不丢配置。
- 内置客户端的 provider/append/custom 目录语义保持。目录选择草稿与策略分开；“使用供应商完整目录”“保留供应商并补充”“使用所选模型”明确表达影响，不因打开、获取、输入或勾选就静默换策略。默认 provider 锁定编辑、只有 custom 可见勾选的原缺陷不得保留。
- 固定映射、已有家族映射和分类模型使用可搜索候选，显示名与真实 ID 分清，支持显式输入未列出的上游 ID；客户端目录不等于上游目标白名单。目录子视图应用后，同一未保存 Key 草稿立即可选，不用保存重开或抄 ID。
- 三个提交边界独立：模型管理保存供应商清单；Key 子选择只应用到外层草稿、外层 Key 保存才写配置；网关保存才写暴露策略。取消当前编辑不保存其草稿，也不撤销此前在其他编辑器已经明确保存的内容。
- idle/查询中/无凭据/空结果/失败分开展示；错误可重试。有效身份包含所选 Key/凭据版本、地址、认证、UA 与供应商头/代理；延迟旧响应不得污染新身份。刷新、空结果、错误、取消不清空已保存或手工模型。
- 既有内置客户端 Base URL 覆盖仍可编辑/恢复，并按原 Key 保存语义生效；独立查询不再读取该弹窗的未保存草稿。历史覆盖证据：[ProviderModal.tsx:285–297](<src/renderer/components/providers/ProviderModal.tsx#L285-L297>)、[KeyEditModal.tsx:539–585](<src/renderer/components/keys/KeyEditModal.tsx#L539-L585>)、[ModelMappingEditor.tsx:243–282](<src/renderer/components/keys/ModelMappingEditor.tsx#L243-L282>)。
- 角色、1M、启动参数和已有映射仅改显式编辑字段，不批量迁移语义。参考 cc-switch 的候选/已配置分离，不引入其依赖、第三方目录或协议转换。

### R6 / R9.3 简化网关连接与严格模型暴露

- 网关不是内置客户端启动台，不选择或继承 Claude Code/Codex 等配置，不增加 `clientKind='gateway'`。一个网关绑定一个 provider/Key，Key 只提供凭据和可用状态；供应商提供默认地址、额外 Header、HTTP Proxy 等公共设置。
- **默认认证已确认**：新建沿用 Bearer，基础表单不要求选择认证；x-api-key/不鉴权放高级设置，已有显式配置保持不变。不新增自动猜测，不把默认解释成免认证。
- Base URL 留空用供应商默认；UA 覆盖放高级设置，未覆盖时遵循请求/供应商默认，不继承内置客户端查询偏好。Header 仍在供应商配置，不新增每网关 Header 编辑器。
- **网关不查看或获取模型**：删除表单预览及二级预览提议，只提供“暴露全部 / 指定模型”和连接设置。指定模型从 R4 清单选择；旧已选 ID 即使不再位于清单仍保留。保存不用先查询，选择全部时不用勾模型；指定模式必须明确选择非空集合。
- **暴露语义已确认**：默认未配置为全部；配置指定集合后，客户端模型列表只展示已选项，手工指定未选 ID 也必须在本地被拒绝。清单获取/刷新/删项不自动修改任何网关的已保存策略，空集合或损坏策略不能回退成全部。
- 全部模式的 `/models`、`/v1/models` 保持既有上游发现；指定模式按显式配置发布这些真实 ID（显示名可来自已保存清单），不是自动选择默认模型，也不保证上游实际可调用。外部客户端仍自行发送 model，网关不重写或映射。
- **兼容性边界已确认**：指定模式下无法验证模型的请求明确拒绝，不能放行绕过；全部模式保留当前 HTTP/SSE/WS 透明兼容。本轮先支持可可靠识别 model 的标准 JSON 推理，原样 WS 及其他无法验证的形式在转发前拒绝，不为本轮新增通用协议适配。代码现状证据：[handler.rs:541–638](<src-tauri/src/proxy/handler.rs#L541-L638>)、[handler.rs:3156–3173](<src-tauri/src/proxy/handler.rs#L3156-L3173>)。
- 校验覆盖所有入口别名/路径形态、缺少/无效/歧义 model 和不支持的端点；不允许替代路径、WS 升级或资源操作绕过限制。允许的请求使用同一连接规则，Body/model 原样；拒绝可诊断、不泄密、不虚构上游推理或 token。
- **高优先级基线缺陷**：保留消除旧 `/models` 优先 Codex/Grok、推理读取 Claude Code 的隐式分流成果；凡实际访问上游均共用有效网关连接。原始证据：[handler.rs:396–426](<src-tauri/src/proxy/handler.rs#L396-L426>)、[handler.rs:1277–1368](<src-tauri/src/proxy/handler.rs#L1277-L1368>)、[handler.rs:1602–1608](<src-tauri/src/proxy/handler.rs#L1602-L1608>)。
- 暴露策略须前后端持久化、校验和迁移成套接通；旧网关缺失策略按全部。保持名称、本地 Key、绑定、启停及显式连接，不重做旧认证迁移，不反向改 Key/供应商/其他出口。绑定变更不默默解除已保存限制。
- 以实际到达 mock 上游的 URL、认证、UA、Header、原始 model 和被拒绝请求零到达为验收，不只看 UI 保存。当前只读模型预览不是已实现的暴露选择器。

### R7 网关请求的供应商线路质量归属与刷新

- 首次点击供应商趋势使用点击项真实 providerId，按网关 token 实际绑定归属，不按外部客户端的显示名猜测。现场 DSH any-router 的 token 实际绑定 agentRouter；anyRouter 默认近一周无记录、近一月有 29 条历史，近期空状态符合数据，不通过篡改统计或 DSH 凭据修补。
- 网关只是入口；已解析 providerId/apiKeyId 的 HTTP/SSE 推理按原统计契约进入供应商/Key 线路质量，不因 session_kind=gateway、无项目或无内置客户端类型丢归属。
- 成功、上游错误、传输失败、取消按现有 outcome 规则记录一次；token/耗时/TTFT 有实测才展示，不估造缺失 usage。
- 线路质量弹窗打开、范围变更、重新打开及页面刷新读取当前 scope；保留范围/视图，旧响应不覆盖新范围。失败与真实无数据分开并可重试。
- 区分供应商卡片“近 24 小时成功率”和详情“线路质量”的来源/范围，不能以卡片刷新代替详情刷新或相加造成重复计数。
- `/models` 等非推理调用不写成计费推理；无法归属的本地拒绝不硬塞给供应商。WS 握手只作为连接指标，不伪装成完成推理或虚构 token；覆盖现有 HTTP/SSE 与 WS 指标边界。
- 先核查 request_logs/聚合再修最小层，不建重复统计、不回填来源不明历史；日志三天清理不清线路质量数据库。现场证据见 [research.md](<.trellis/tasks/10-28-gateway-console-provider-ux/research.md>)；刷新/错误态缺口独立验收，不冒充现场根因。

### R8 网关局域网访问

- 原回环绑定的证据：[runtime.rs:76](<crates/cc-use-daemon/src/runtime.rs#L76>)。保留显式“局域网访问”能力：默认 `127.0.0.1`，用户开启才监听 `0.0.0.0`，与现有 proxyPort 共用；不能仅展示 LAN 地址而未改变监听。
- 开启后网关/设置页展示可复制的本机 LAN IPv4 入口与网卡名；不支持 IPv6 入口或指定单网卡，界面明确说明。
- `/_management/*` 始终只接受 loopback（127.0.0.1/::1）对端，非 loopback 返回 403；管理 token、日志清空与 SSE 管理通道不能外露。
- LAN 对端只能用网关/会话本地 Key；provider 真实凭据 pass-through 从非 loopback 拒绝，避免开放中继。本机原有行为及网关透明转发/归属不因来源改变。
- 修改监听范围与端口变更一样，保存后自动重启 daemon，失败可见，不静默保留旧值；缺失字段按仅本机，持久化与升级/回滚兼容。
