# GUI 主链路改版：信息架构与技术设计

## 1. 产品定位与完整交付

GUI 负责概览、准备线路、运行控制、桌面接入与观测；CLI 是终端启动入口。使用一个集成任务组织同一版交付：各工作包有独立测试，但不发布新旧交互并存的过渡版本。

## 2. 导航与页面职责

| 一级入口 | 目标路由 | 职责 |
| --- | --- | --- |
| 概览 | `/` | 当日统计 + 年度热力图；从数字和日期进入统计 |
| 运行实例 | `/instances` | Claude Code/Grok 合并列表，默认正在运行；客户端筛选、最近结束记录、换线 |
| 桌面接入 | `/desktop?client=codex` | Codex/Claude Desktop 切换；线路、配置状态、预览、恢复 |
| 供应商与密钥 | `/keys` | 供应商与密钥配置、额度、模型清单、顺序管理 |
| 网关出口 | `/gateway` | 外部接入地址与鉴权、绑定线路、独立连接配置与模型暴露范围 |
| 用量统计 | `/stats` | 时间/来源范围一致的汇总与完整分页请求账本 |
| 控制台 | `/console` | 请求/异常/运行日志的终端单行流；请求定位和留存提示 |
| 设置（底部） | `/settings` | 全局、CLI 安装、备份、外观等现有能力 |

导航按「使用 / 配置 / 观测」轻量分组，概览置顶。统一页头、操作栏、内容区域和刷新状态。保留侧栏折叠、原生标题栏拖拽及主题能力。

旧入口重定向：`/claude-code` → `/instances?client=claude_code`，`/grok-build` → `/instances?client=grok`，`/codex` → `/desktop?client=codex`，`/claude-desktop` → `/desktop?client=claude_desktop`。只替换 location，不丢弃合法观察参数。未知路径仍回概览。

## 3. 页面骨架与交互

### 3.1 概览

```text
概览                                  [年份]
[今日 Token]      [今日请求]      [今日失败]

年度活动热力图（主视觉与完整年度跨度）
  本地日期格 → 对应日期请求账本
```

不加入项目、最近启动或重复客户端导航卡。热力图的年份切换、精确数值、今日识别保持；加载失败不是零用量，显示重试。格子可键盘聚焦/Enter 打开，不属于所选年份的补位格与未来格禁用。今日失败入口对齐当日失败指标的口径。

### 3.2 运行实例

```text
运行实例                  [Claude 会话] [客户端设置]
[全部 | Claude Code | Grok]          [正在运行 | 最近结束]
目录 / 实例短码   客户端   状态   当前线路      操作
cc-use / K7P2     Claude   运行   A / 工作号    换线 · 请求
```

- 目录只是实例身份信息；同一目录多个实例不得合并成一个操作对象。
- 活跃列表必须完整：读取现有无参数活跃接口，再按客户端筛选；历史分别读取两客户端最近记录，不把各100条上限误当全量。合并去重且标注历史范围。
- 显式识别 `launching/running/stale`，stale 不伪装为正常运行。旧 `claude` 别名归一化。
- 换线使用统一选择器，按目标实例真实客户端过滤。仅影响此实例的后续请求，不修改项目默认、其他实例或在途请求。
- 行级提交中；失败保留选择，重新读取该实例状态并显示可操作原因。刷新与提交的响应均需身份/版本防过期保护。
- Claude 会话是次级视图 `/instances?view=sessions&client=claude_code`，保持现有查看/恢复能力，不与 managed-instance 历史混为一谈。客户端设置保留 Claude 专属环境配置与终端工具；不虚构 Grok 对应能力。
- 无实例展示在终端运行 `cc-use claude` / `cc-use grok` 的说明与复制，不在 GUI 执行命令；缺少线路则提供配置入口。

### 3.3 项目退出边界

移除主窗口项目管理/启动、项目统计入口和托盘「最近项目」启动子菜单，避免 GUI 留下第二套启动入口。保留托盘打开主界面、每日用量、桌面端换线及其他现有非项目功能。

项目数据库、绑定、CLI 最深路径匹配、前置命令、共享启动逻辑、导入导出和旧 IPC 保留；不调用项目删除、不执行清理迁移。CLI 仅将不再准确的「GUI 默认」说明改为「已保存默认」，不改变选择/执行行为。历史请求中的目录/名称可保留为详情信息，不提供项目管理或聚合入口。只删除确认无其他消费者的 renderer 项目组件与样式；不要连带删除共享契约。

### 3.4 桌面接入

Codex / Claude Desktop 共用页面骨架和状态呈现，各自保留配置实现与兼容判断。页头切换客户端，主区展示配置事实、绑定供应商/密钥/模型；主按钮选择或更换线路；配置预览与恢复官方为次级操作（恢复须确认）。

状态不再使用单一 boolean 或「线路已生效」：

- 正在读取：加载中，不先闪出官方状态。
- 官方/未配置：提供选择线路；检测失败独立展示重试，不等价于未接管。
- 接管配置存在：显示「已配置接管」，读取真实持久化路由，不以 renderer 的 last-key 缓存充当真实状态。
- 本次仅网关绑定改变：显示网关线路已切换；没有新增客户端重开要求。
- 客户端配置改变/恢复官方：显示配置已更新与「完全退出并重新打开以加载」的页内说明。
- 无法证明客户端重新加载：不提供假自动确认；新请求、进程存在、收起说明均不代表已加载。

建议结构化契约（字段名实施时在 Rust/TS 同步）：

```ts
type DesktopOperationResult = {
  clientKind: 'codex' | 'claude_desktop'
  action: 'takeover' | 'switch_route' | 'restore'
  completion: 'complete' | 'partial'
  routeChanged: boolean
  configChanged: boolean
  modelCount: number | null
  nextAction: 'reopen_client' | 'none'
  updatedAt: string
  warning?: string // 已脱敏；partial 必须给下一步
}
```

统一 `getApi().desktop`（或现有接管命名空间）封装读取与操作；不解析后端成功文案来判断逻辑。旧调用方同步适配，托盘只做结果呈现。

通过已有 settings 保存各客户端最近配置变更说明/时间及版本，不新增数据库实体。持久化在共享后端完成，覆盖托盘、密钥编辑引发的模型重写、启动同步。配置内容无变化的同步不能反复制造新提示；仅切线路不能覆盖之前仍有价值的配置变更说明。老安装无操作记录时显示通用加载说明，不捏造变更时间。

Codex 复用现有完整配置比较；Claude Desktop 若要宣称无需重开，必须比较 profile、部署模式、meta 等实际相关配置。否则保守作为配置写入处理。文件操作失败时考虑已有文件快照与 session 更新顺序：优先恢复一致性；无法回滚的部分成功必须回读实际状态并报告，不能提示「全部成功」或承诺「完全没改」。partial 必须提供重试/恢复动作；回读也失败时显示 unknown，不按旧快照猜测。密钥已保存但自动桌面配置同步失败时，分开报告「保存成功 / 配置同步失败」，失败记录须可回读，不能只写日志或生成假的配置成功时间。

### 3.5 供应商密钥与统一选线

供应商筛选/摘要 + 紧凑密钥列表；额度与5h/周/月窗口保留可见，不为紧凑隐藏核心信息。供应商模型清单仍是唯一模型管理入口，Key 编辑只选择/映射，不新增重复模型管理页。

选择器将展示与业务能力分开：

- 客户端上下文按支持类型、供应商/密钥启用、耗尽状态校验。
- 网关上下文使用网关既有校验，不暗中套某客户端兼容规则；换线不得重置或放宽已有 modelPolicy 与模型 ID（包括旧缺失 ID），目录读取失败也不修改它们。只有用户显式编辑策略并保存才改变模型暴露范围。
- 显示名称、模型摘要、现有额度及计量窗口、更新时间、当前标记、不可用原因。未知额度不是0；缓存不是实时健康检测。
- 不在选择器里做排序维护或背景自动刷新额度；提供明确手动刷新。顺序管理仍留在资源页且保留其既有 CLI 预选影响。
- 空列表区分无资源、无兼容项、全部不可用、搜索无匹配；给添加/调整兼容配置/清除搜索的正确动作。

就地补齐采用同一对话框宿主的分步视图，而非无限叠加弹窗：`选择 → 新增供应商（可选） → 新增密钥 → 返回选择`。复用现有表单与提交服务；创建完成返回新实体ID，刷新数据并选中新密钥，仍需用户确认应用线路。取消/失败回到上一步并保留原操作上下文；外部轮询不得覆盖草稿。

保存与额度查询分离：持久化成功即结束保存；保持原有按需自动查询，但异步刷新缓存。查询失败只标记额度更新失败，不把已保存的密钥报成保存失败。新供应商保存后自动定位其分组，不被之前筛选隐藏。

### 3.6 网关

保留独立入口和独立配置模型。列表优先呈现名称/启用、地址、绑定线路、风险与复制；编辑以绑定线路、连接参数、模型暴露范围分区。高级设置收起但旧值可见且不会因未展开被清空。保持 Bearer 默认、token 显隐/复制、LAN 地址语义、selected 模型严格拒绝、缺失旧 ID 保留；不将选择密钥的模型映射继承为网关策略。

## 4. 观测契约与安全边界

### 4.1 账本查询

共享 `RequestLogFilter` 包含 `providerId?`、`apiKeyId?`、`instanceId?`、`outcome?`、`population?: 'all' | 'with_usage'`。时间继续使用现有 `StatsTimeRange`（含本地 custom 日期）；筛选值需白名单解析，无效日期或未知项显示可清除的错误，不得静默回全量。今日请求及热力图请求数仅计有 Token 的记录，钻取携带 `with_usage`；今日失败沿用 `outcome IS NOT NULL AND outcome != 'success'`。通用账本默认 `all`，两种分母不能混写成相同请求总数。

统计汇总、趋势、总数与分页行使用同一个后端参数化 WHERE builder；筛选必须发生在聚合/COUNT/LIMIT 前。失败口径与首页失败指标一致；从有用量范围切换失败时，同时切回 `population=all`，避免交集为空。客户端筛选只用于实例列表，不对缺少客户端历史快照的账本新增client筛选。实例通过 `request_logs.session_id = managed_instances.session_token` 与稳定实例ID关联，token只留后端，绝不进入URL、剪贴板、错误或截图。

URL只携带非敏感资源ID、日期、结果枚举、分页和请求ID；目录路径、凭据、完整session token与模型/查询草稿不得进入URL。过滤变化重置分页；返回、⌘R保留合法scope。provider/key/instance已删除或关联消失时，显示范围失效/历史关联不可用，不用同名对象猜归属或降级全量。历史账本数据仍保留。

### 4.2 请求账本 → 控制台

使用现有贯通的 `requestId` 定位事件，不扩展控制台为资源分析器。新增窄只读 `console.readRequest(requestId)`（或等价精确过滤），在持久化留存范围内匹配后再限量；不能只在内存500条中找。返回事件及留存/截断元信息，并区分读取失败与无匹配。精确定位结果使用独立只读投影，不塞回全局500条缓冲后被裁掉；受清空generation约束，迟到结果不能复活已清除内容。

控制台显示一个可清除的请求定位标记，保留终端单行流、请求/异常/运行日志视图、搜索、暂停/继续、详细模式、复制、全局清空语义。运行日志不假装属于某实例。找不到请求时说明「未收录、已清除或不在保留范围」；只有已知日期超窗才明确过期。返回账本恢复原筛选；统计可携带原始定位上下文，不能虚构运行日志关联。

不新增日志页，不重写事件落盘格式，不扩大留存、不改统计采集或token口径。

## 5. 视觉、可访问性与实现边界

使用现有 Ant Design 6、theme token、CSS modules、Zustand与HashRouter，不换组件库、不引入新数据请求框架。常规窗口1440×1000与900×700均验证；窄窗口只允许密集表格或热力图必要的局部横向滚动，不整页溢出。保留浅/深主题、reduce-motion、双语、可见focus与图标aria-label。

抽取少量共享页面标题/状态块/线路摘要，不建通用低代码页面配置引擎。统计保留趋势与资源质量/用量视图，资源弹窗可增加「查看请求」链接而非砍掉已有分析能力。设置仅统一页面层级与入口，不重写导入导出、升级、CLI安装等内部行为。

## 6. 风险与回退

- 查询过滤是新增只读能力，IPC可选参数默认保持现有全量行为；SQL按索引与真实条件验证，避免非索引名称搜索。
- 桌面接管涉及真实文件与session，必须先用临时目录/测试库验证状态与失败回读；未经额外授权不以真实客户端做写入验收。
- 项目下线仅删入口，数据库与共享API保留，因此可通过代码回退恢复界面，无需数据迁移。
- 开发浏览器使用纯fixture API，无法访问真实IPC/Keychain/daemon；demo入口仅开发环境启用，缺失fixture方法明确报错，禁止回落真实API；验证浏览器网络只允许当前静态预览源，拦截其他HTTP/WebSocket，真实Tauri全局不存在时仍不可绕过fixture。
- 不提交、不发布、不升级依赖、不自动重启现有daemon或用户客户端。最终以完整集成测试与设计验收交付。
